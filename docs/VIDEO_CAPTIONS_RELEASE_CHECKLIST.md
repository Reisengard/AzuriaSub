## Export check (automated, real browser, real H.264)

`dev/export_chrome_check.js` serves the built app on 127.0.0.1, starts Chrome with a fresh profile and drives the app over the DevTools protocol. It imports each fixture through the app's own file inputs, sets up captions through the caption store, and exports with `J.CaptionVideoExporter`, the exporter behind the Export button. The one difference: it writes to memory, or to an OPFS file for the long case, instead of opening the save dialog. Each MP4 is then opened in Chrome (`<video>` metadata, seek to the end) and fully decoded by FFprobe (`-count_frames`). Reports and outputs: `dev/fixtures/media/generated/export-check/final-{headless,headed,edge}/` (gitignored).

## Supported path and fallback

- **Supported:** latest desktop Chrome or Edge. Export is H.264 (`avc1.420033`, 8 Mbps, 30 fps) through WebCodecs, muxed by Mediabunny, with the source AAC passed through bit-exact when the video is not trimmed, or re-encoded to AAC (192 kbps) when kept sections change the timing.
- **Up to 30 s and 128 MB of source:** in-memory export, then a download. **Longer:** the user picks a save location (`showSaveFilePicker`) and the file is written as it is encoded. Browsers without it get `MEDIA_FILE_SAVE_REQUIRED` before any work starts.
- **H.264 encoding unavailable** (checked with `VideoEncoder.isConfigSupported` before any frame is encoded): the export stops with `MEDIA_ENCODER_UNSUPPORTED` and guidance. There is **no second caption encoder in the app**. The fallback is the project file: save it, open it with the same video (relink) in a supported browser or on another computer, and export there; nothing is lost. The export dialog can also write the captions as an SRT file ("Export .srt file"); it needs captions but no video and no encoder, so it works where H.264 export does not.
- **Audio:** a non-AAC soundtrack is refused when the export opens the source, before any frame is encoded (`MEDIA_AUDIO_CODEC_UNSUPPORTED`); audio is never dropped silently. Silent sources export without an audio track.
- **Switching away during export** is fine (verified). Import and preview wait until the tab is visible again (Chrome's background media deferral).

## CI and H.264

There is no CI configuration in the repository. `npm test` (`dev/run_all.js`) runs the export and media tests with mocks, because the bundled test runtime has no WebCodecs and typical headless Linux Chromium builds lack an H.264 encoder. Real encoding is verified on a developer machine with Google Chrome by `npm run check:export-chrome` (in `dev/`): headless by default, `--minimize-export` for a headed window, `--chrome <path>` for Edge. Run it before a release and after any change to media import, the compositor or export. If CI is added, this check belongs on a Windows or macOS runner with Google Chrome installed, not on stock Chromium.
